# Architecture

Redline Racer is an arcade racing game in pixelated 3D (three.js), played in the browser: solo, 2 to 4 players on one screen, or online peer-to-peer. It has 12 maps; each one has its own track layout, car, radio stations, scenery and HUD, and the synthesised music reacts to the race. It is a static site with no build step and nothing to install.

Code, comments and docs are in English. On-screen game text is written in French capitals and translated at display time by `src/engine/lang.js` (the game is bilingual). Paths in this doc start at the repo root.

## How the code fits together

### Load order

`index.html` loads `vendor/three/three.classic.js` (sets `window.THREE`), then every other script with `defer`, in this order:

1. `src/data/maps.js`, `gold-laps.js` (data)
2. `src/engine/sim.js`, `session.js` (no rendering)
3. `src/audio/samples.js`, `instruments.js`, `audio.js`
4. `src/render/textures.js`, `shapes.js`, then each map's `textures-<map>.js` and `shapes-<map>.js`, then `textures-cars.js`, `shapes-cars.js`
5. `src/render/scenery.js` (creates the empty `SCENERY` and the shared helpers `PLACERS`), then every `scenery-<map>.js`
6. `src/engine/lang.js`, `devices.js`, `network.js`, and last `game.js`

Scripts share globals on `window` (`MAPS`, `MAP_DEF`, `buildTrack`, `SCENERY`, `SOUND`, …). `sim.js`, `session.js`, `lang.js` and `devices.js` also load under Node with `require`, which is how the tests use them.

Loaded on demand, not by `index.html`: `src/audio/instruments-notes.js` (sampled notes, 3.7 MB; loaded at the first radio station, oscillators play until then), `vendor/peerjs.min.js` (loaded by `withPeer` in `network.js` when a room is opened or joined), `src/engine/hitbox.js`, `tools/perf.js`, `tools/profile.js`.

### sim.js vs game.js

- **`src/engine/sim.js`** is pure: no three.js scene, no DOM, no random numbers. `buildTrack(THREE, map)` turns a map entry into a track `T` (samples `T.S`, count `T.n`, half-width `T.W`, the map `T.map`, the car `T.car`, driving tuning `T.kt`, surfaces, rain zones, relief). It reads no global map, so several tracks can live side by side. It holds the car (`newCar`, `step`), walls and relief (`ground`, `wallFace`, `slope`), the autopilot (`autopilot`, `driveSkid`), races (`newRace`, `stepRace`, `raceOrder`), Tour scoring (`tourAll`), traffic (`traffic`), medal reference lap (`lapRef`, `stretch`), challenge links (`challengeCode`, `challengeRead`) and damage wear (`wear`, `brokenImpact`). Everything it exports is listed in the `Object.assign(G, { … })` at the end of the file.
- **`src/engine/session.js`** is the game flow on top of the sim (records, medals, ghosts, Tour rounds), with storage passed in as plain `{ get, set }` objects so Node can test it.
- **`src/engine/game.js`** draws, plays sound, reads inputs and calls the sim and the session. It is one closure, `window.launchGame(map, backdrop)`, split into sections you find by searching `// ----------`: rendering and final pass, the three scenery entities, dynamic lighting, track geometry, map scenery, car and effects, damage, destructible scenery, merge of static scenery, audio glue, game state, online, HUD, loop.

### Game loop

`frame(now)` in `game.js`, driven by `requestAnimationFrame`:

1. Poll inputs (`PER.poll`, `PER.entering`); each view (`vu`) gets its input, or the autopilot's (`?auto`, demo, player finished).
2. Physics runs in fixed steps of `H = 1/120` s: `for (acc += dt; acc >= H; acc -= H)` calls `stepRace` (in a race, one input per human) or `step`.
3. Before drawing, each car is pushed forward by the leftover `acc` at its speed (and the traffic clock `tTraffic`), then put back after the frame. This keeps motion smooth at 60, 120 or 144 Hz without changing the physics.
4. For each view: place its camera, set lights, fog and rain for its car, draw its HUD, render the scene into its 270-line target, then run the final pass (speed blur, quantisation, dithering, scanlines) into its part of the screen.

### Maps

A map is an entry of `MAPS` in `src/data/maps.js` (layout, width, grip, car, radio, theme `th`; the field list is the comment at the top of that file) plus its folder `src/maps/<map>/`:

- `textures-<map>.js` adds to the texture catalogue (what a surface looks like),
- `shapes-<map>.js` adds to the shape catalogue (geometry, or assemblies of boxes with named zones),
- `scenery-<map>.js` adds its scenery function with `Object.assign(SCENERY, { <map>(h) { … } })`: where to put which shape with which texture, through the helper object `h` (`h.pose`, `h.geo`, `h.mat`, `h.emis`, and `PLACERS`: `inst`, `insts`, `boxMesh`, `edgePt`, `marker`, `weld`, `near`, `pt`, `terrain`).

A map also needs a place in `EVENING` (Tour order and time of night), a gold trace in `src/data/gold-laps.js` (`node tools/build-gold-laps.js <map>`), and an English title (`HEADING_EN` in `lang.js`, or `th.hud.heading`). Each new file must get its `<script defer>` line in `index.html` at the right place in the load order; `tests/test-maps.js` fails if `scenery-<map>.js` is missing from `index.html` or if any of the above is missing.

`?map=attempt&grip=…&ground=…&car=<map>` opens a driving test track that is not in `MAPS` (end of `maps.js`).

### Map switching

Changing map does not reload the page. Each map gets its own `launchGame` instance, kept in `window.__maps`. After the first map is shown, the others are built in the background, neighbours first, one at a time (`prepare`, `built`; skipped with `?auto`, `?perf`, `?style`). Switching calls `wakeup()` on the old instance (stops drawing and listening, keeps the GPU resources) and `resumes()` on the new one. The renderer and the sound engine are shared. `ending()` stops an instance (loop and every listener, through one `AbortController`); `frees()` frees its GPU resources. Anything you add that hooks into the page (listener, timer, DOM element) must be undone there.

### Split screen

`VIEWS` in `game.js` holds one view per player (1 to 4; `players(n)` adds or removes views; grid `grid(n)`: stacked for 2, 2 × 2 for 3–4). A view carries its camera, render targets, HUD canvas and all per-camera smoothed state (heading, pitch, shake, nitro and tunnel fades, displayed RPM, light sorting, rain drops, banners), plus the player's device (`vu.periph`), input (`vu.inp`), finished (`vu.finished`) and eliminated-spectator (`vu.spec`) flags. The player's car is `race.cars[vu.n]`; humans come first in the car list.

- The sim runs once per frame for everyone; each view then renders separately, each at 270 lines.
- Shared screens (menu, join screen, pause, results) are drawn once on a full-screen overlay (`COM`, `screens()`), without the final pass.
- Modes with 2+ players: `MODES2` (`raceCase`, `broken`, `elim`, `glisse`). Nothing is saved with 2+ players: no record, medal, ghost, trophy or Tour.
- Sound: engine, gearbox and tyres once per player; radio, ambience, tunnel and rain follow the best-placed player still racing.
- `?players=2` forces the player count; `?auto&players=2` drives every car with the autopilot (captures, benches).

### Inputs and gamepads

`src/engine/devices.js` puts the keyboard, gamepads (Gamepad API) and Joy-Cons (WebHID, Chrome/Edge, J key to allow, two at most) behind one interface. Devices are named `keyboard` (whole keyboard, solo), `keyboardLeft` / `keyboardRight` (left/right halves), `controller<n>`, `joycon<n>`. `poll()` turns gamepad buttons into menu key events, so menus are not duplicated; `entering(periph)` gives the driving input of one device; `enroll()` hands out seats on the join screen (`PLACES`, kept for the session). Driving keys are read by physical position (ZQSD = WASD on QWERTY); other commands by the typed letter. `pages/gamepad.html` diagnoses a gamepad. Tested by `tests/test-devices.js` with fake devices.

### Online

`src/engine/network.js`: no server of our own. Browsers talk peer-to-peer over WebRTC through PeerJS; the public PeerJS server only connects them, by a 4-letter room code (`?room=CODE`). The host runs `stepRace` for everyone; guests send their input and display the received state 100 ms late, interpolated. Needs HTTPS or `localhost`; some strict networks (no TURN relay) cannot connect.

### Storage

Records, ghosts and preferences live in `localStorage`: `vpr7.*` for `ville` and `vpr7.<map>.*` for other maps, `vpr8.tourAll` (Tour progress), `vpr7.trophy`, plus unversioned UI keys (`vpr.map`, `vpr.language`, `vpr.boxMesh`). Hand-offs between map instances use `sessionStorage` (`vpr.menu`, `vpr.go`, `vpr.demo`, `vpr.netgo`). The physics version `CHALLENGE_V` in `sim.js` is used by challenge links and record keys; when physics changes enough to make old times meaningless, bump it.

Challenge links carry a lap in the URL fragment (`#challenge=<version>.<map>.<data>`): positions and heading 5 times per second, never inputs, because the sim does not give exactly the same result in every browser.

## Technical choices

| Choice | Why |
|---|---|
| No build step, plain scripts with `defer` | open and edit anywhere; what you read is what runs |
| Works from `file://` (double-click `index.html`) | Chrome refuses ES modules on `file://`, so `index.html` loads `vendor/three/three.classic.js`, a classic-script copy of three made by `node tools/three-classic.js` |
| three.js r187 vendored in `vendor/three/`, no CDN | works offline; pinned behaviour. `three.module.js` is patched (lines marked `// vpr`: array uniforms re-sent only when changed). Redo the patch on any three update, then rebuild `three.classic.js`; `tests/test-three-classic.js` checks it is current |
| WebGLRenderer, not WebGPU | the custom lighting, wet-road reflections and final pass are GLSL injected through `onBeforeCompile`, which WebGPURenderer does not take |
| Static hosting on GitHub Pages (`main`, root) | no server; online play is peer-to-peer |
| Low resolution (270 lines per view), nearest filtering, dithering, scanlines | the pixelated look; also keeps pixel cost low |
| All music and most sound synthesised live (`src/audio/audio.js`) | small download, adaptive music |
| Heavy assets loaded late, Japanese font subset (`assets/fonts/dotgothic16-game.woff2`, rebuilt by `python -I tools/font.py`) | first load under budget on GitHub Pages |
| Physics separate from rendering, at 120 Hz | testable under Node, stable at any refresh rate |

## Run the game

- `python tools/capture.py 8123`, then open <http://localhost:8123/>. This server disables browser caching; with `python -m http.server` the browser can mix an old `sim.js` with a new `game.js` and the race crashes at the countdown. In Claude Code, the `game` configuration of `.claude/launch.json` runs the same server.
- Or double-click `index.html`.
- `pages/listen.html` (sound bench) and `pages/editor.html` (music editor) are served by the same server. Editor settings are stored in the browser; to hear them in a race, open the game on the same host and port.

URL parameters: `?map=<map>`, `?auto` (autopilot drives), `?players=1..4`, `?perf` (benchmark), `?hitbox` (collision limits), `?opt=<JSON>` (merge options into the map, see MAP-ENGINE-OPTIONS), `?style=<name>` (compare visual styles), `?room=CODE` (join a room). `window.__g` exposes the current map instance in the console.

## Where to tune what

In `src/data/maps.js`, per map:

| Field | Effect |
|---|---|
| `W`, `sc`, `pts`, `wide` | road half-width, layout scale, control points `[x, z, altitude]`, wider stretches |
| `grip` | lateral grip (m/s²): 44 on `ville` (arcade), 15–24 elsewhere |
| `car` | gears, torque curve, mass, aero, traction, `look.type` (model in `src/render/shapes-cars.js`) |
| `tun`, `hotList`, `sect`, `amb` | tunnel, sector where the music goes wild, split times, ambience-sound zones (point indices) |
| `camH`, `spd`, `kmh` | camera height, speed range of speed effects, speedometer factor |
| `radio` | the stations (data in `RADIO` at the top of the file) |
| `th` | theme: sky, fog, lights, road colours, `th.scenery` (which `SCENERY` function), engine options |
| `th.hud` | HUD style, rev gauge (`gauge`), `mph`, Japanese labels (`jp`), title |
| `th.rainFx` | rain: `1` everywhere, or zones `[a, b, force]` |
| `surf` | road surface: `{ backdrop, zones: [[a, b, surface, force]] }`; coefficients per surface in `SURF` at the top of `sim.js` |
| `jumps`, `trough` | relief: jumps and rideable banked walls; gives the car height and gravity (`GRAV`, `DROOP`, `LAND*` in `sim.js`) |
| `grav`, `evenJump`, `dents`, `bowls` | with relief on: free-fall gravity of the map (9.81 by default; `lune`: 8); `[speed, power, floor]` that lightens it for a car taking off slower than `speed` (jump lengths close to each other); `[[x, z, radius, depth], ...]` small bowls dug in the ground under the car; `[[x, z, floor radius, rim radius, height, power, ...]]` a crater whose wall the car drives up, with a tunnel allowed under it (`T.dent` gives both to the scenery for its terrain; see `buildTrack` in `sim.js`) |
| `traffic`, `rivals`, `med` | trucks on the road, rival names, medal ratios |
| `th.objects`, `th.isFar` | knock-over objects, minimum camera far distance |

In `src/engine/sim.js` (top of file): `TOP` (reference speed for steering and effects), `KT0` (driving tuning), `NI` (nitro), `GL` (drift scoring), `DIFF` (race difficulties), `AI_LVL` (rival levels), `SURF`, `CHALLENGE_V`.

In `src/engine/game.js` (search for it):

| Search | Effect |
|---|---|
| `NL`, `BRIGHT_GAIN` | dynamic lights: number computed, strength |
| `QUANT`, `WEFT`, `SHAKES` | retro rendering: colour levels, Bayer dithering, vertex wobble |
| `emis = (` | one scene light (also `h.emis(` in `scenery-<map>.js`) |
| `LU_F` | lighting code added to every material |
| `post.uniforms.amt` | speed blur |
| `cam.fov` | speed-dependent field of view |
| `function drawHUD` | HUD and screens |
| `pauseItems` | pause menu entries |
| `OPP`, `SPIKES` | rival colours and taunts |
| `GLM` | drift-mode medal thresholds per map |
| `DEMO_WAITING` | idle time before the demo starts |

In `src/audio/audio.js`: `function sched(` (music sequencer and adaptive layers), `function audioFrame(` (engine, tyres, wind, music driven by the race), `rainFrame` (rain sound).

## Performance budgets

Frame budget (`BUDGET` in `tools/perf.js`), measured on an autopilot race lap against 3 rivals:

| Measure | Solo | Per view, 2 players (`budget(2)`) |
|---|---|---|
| `drawCallsMax` (draw calls per frame, shadows included; machine-independent) | ≤ 300 | ≤ 600 |
| `ms` (mean frame time, GPU included) | ≤ 3 ms | ≤ 8.3 ms |
| `msMax` (worst half-second) | ≤ 4.5 ms | ≤ 8.3 ms |
| `cpuMax` (worst single frame) | ≤ 8.3 ms | ≤ 8.3 ms |

Smoothness (`REGULARITY` in `tools/perf.js`): `judder` ≤ 5 %, `judderMax` ≤ 15 %. Load (`BUDGET` in `tools/load.js`): ≤ 2.5 MB transferred (gzip), ≤ 60 requests, ready in ≤ 6 s, warm visit ≤ 3 s. Memory: `chain()` must show the same counts of geometries, textures and shaders on the second pass through all maps as on the first.

Milliseconds depend on the machine and its load (reference: laptop with integrated Intel Arc 140T); compare versions back to back. Draw calls and vertices do not: compare those before and after a change. At the last measurement, some maps were above 300 draw calls (`perse`, `wangan`, `barrage`, `plage`, `paris`, `chapada`). What keeps the numbers down is listed in [CODE-QUALITY.md](CODE-QUALITY.md#performance-rules).

To fix a failing map: verdict on all maps → classify (`ms` too high = steady cost; `cpuMax` = isolated hitch; a hitch that does not repeat at the same place is the machine) → `--profile <map>` → fix in the map's files first (merge, share materials, fewer vertices, drop needless `castShadow`) → re-profile, capture the area, rerun the bench on all maps and `tests/test-maps.js`.
